# 용어

한 줄 정의입니다. 자세한 설명은 CLAUDE.md 3장(괄호 안 번호)에 있습니다. 새 용어가 나오면 해당 묶음에 추가합니다.

## 광고 생태계 (3-1)

- **광고주**: 돈을 내고 광고를 거는 쪽(브랜드, 입점사).
- **매체(퍼블리셔)**: 광고 지면을 파는 쪽. 리테일 미디어에서는 쇼핑몰 자신.
- **애드 서버**: 요청마다 어떤 광고를 낼지 정하고, 그 결과를 측정, 과금하는 서버.
- **지면(슬롯)**: 광고가 들어가는 자리. 예: 홈 상품 목록의 두 번째 칸.
- **DSP**: 광고주 쪽 구매 도구. 여러 매체 지면에 자동으로 입찰합니다.
- **SSP**: 매체 쪽 판매 도구. 지면을 여러 DSP에 팔아 가장 비싼 값을 받습니다.
- **RTB / OpenRTB**: 노출 한 건마다 하는 실시간 경매 / 그 요청, 응답 형식의 표준(IAB Tech Lab).
- **리테일 미디어**: 쇼핑몰이 자기 지면과 자기 구매 데이터로 파는 광고.
- **클로즈드 루프**: 노출부터 구매까지 한 회사 데이터로 이어 볼 수 있는 구조.
- **Sponsored Products**: 일반 상품 목록 사이에 섞여 나오는 상품 광고. 이 저장소가 다루는 형식.

## 서빙 (3-2, 3-4)

- **서빙 경로**: 요청 → 후보 → 예측 → 랭킹 → 옥션 → 응답. 동기이고 수십 ms 안에 끝나야 합니다.
- **측정 경로**: 노출 → 클릭 → 전환 → 과금. 비동기이고 늦어도 되지만 정확해야 합니다.
- **후보 추리기**: 타게팅이 맞고 예산이 남은 광고만 남기는 단계.
- **pCTR / pCVR**: 예측 클릭률 / 예측 구매 전환율. 이 저장소에서 pCTR은 광고별 고정값.
- **랭킹**: 후보를 기대 수익(eCPM) 순으로 줄 세우기. 입찰가 순이 아닙니다.
- **1등가 옥션(first-price)**: 낙찰자가 자기 입찰가를 냅니다.
- **2등가 옥션(second-price, GSP)**: 낙찰자가 그 순위를 지키는 데 필요한 최소 금액만 냅니다. 낙찰 CPC = 2등 eCPM ÷ (내 pCTR × 1000) + 최소 단위.
- **최저가(reserve price)**: 이 아래로는 팔지 않는 바닥 가격.
- **노출 토큰**: 서빙 응답에 담아 보내는 서명된 고유 ID. 노출, 클릭이 이걸 달고 돌아와야 어떤 경매, 어떤 가격의 광고였는지 알 수 있습니다.
- **채움률(fill rate)**: 광고 요청 중 실제로 광고를 채워 응답한 비율. 빠진 만큼이 매출 손실.
- **서킷 브레이커**: 호출이 반복해서 실패, 지연되면 한동안 호출 자체를 건너뛰는 장치.
- **왕복 시간(RTT)**: 요청을 보내고 응답을 받기까지 걸린 시간. 리전이 다르면 커집니다.

## 지표와 과금 모델 (3-3)

- **CPM / CPC / CPA, CPS**: 노출 1,000회당 / 클릭당 / 전환(구매)당 과금.
- **CTR**: 클릭 ÷ 노출.
- **CVR**: 전환 ÷ 클릭.
- **ROAS**: 광고로 생긴 매출 ÷ 광고비.
- **eCPM**: 과금 방식이 달라도 "노출 1,000회당 기대 수익"으로 맞춘 값. CPC 입찰이면 입찰가 × pCTR × 1000.
- **CTR 부풀림**: 클릭은 정확한데 노출이 유실되면 분모가 줄어 CTR이 실제보다 커지는 현상.

## 예산 (3-5)

- **예산 집행 속도 조절(budget pacing)**: 하루 예산이 오전에 다 써지지 않게 고르게 나누어 쓰는 것.
- **throttling**: 확률적으로 입찰 참여를 줄여 소진 속도를 늦추는 방법.
- **초과 집행(overspend)**: 이벤트 지연, 서버 분산 때문에 예산보다 더 많이 과금, 노출되는 것.
- **소진 표시**: 예산이 다 된 광고를 서빙에서 빼도록 Redis에 남기는 표시. 장부에서 언제든 다시 계산할 수 있는 파생 값.

## 이벤트 수집 (3-6)

- **노출(impression)**: 광고가 기기에 전달되어 렌더링을 시작한 시점에 세는 이벤트(IAB/MRC). "봤다"는 뜻은 아닙니다.
- **뷰어빌리티**: 디스플레이 광고 픽셀 50% 이상이 1초 연속 화면에 보인 노출(동영상은 2초).
- **유실 / 중복**: 앱 종료, 네트워크 끊김으로 이벤트가 사라지는 것 / 재전송으로 같은 이벤트가 두 번 오는 것.
- **대사(reconciliation)**: 서로 다른 집계(이벤트 수, 과금 수, 금액)가 맞는지 맞춰 보는 확인 작업.

## 어트리뷰션 (3-7)

- **어트리뷰션**: 전환을 어느 광고, 어느 유입 덕분으로 볼지 정하는 규칙.
- **click-through / view-through**: 클릭 후 전환 / 클릭 없이 노출만 보고 난 뒤 전환.
- **어트리뷰션 윈도우**: 광고 후 며칠 안의 구매까지 그 광고 성과로 인정할지의 기간.
- **Affiliate**: 공유 링크에 추천인 ID를 붙여, 기간 안 구매에 수수료를 주는 방식.

## 부정 트래픽 (3-8)

- **IVT(무효 트래픽)**: 과금하면 안 되는 트래픽.
- **GIVT**: 알려진 봇, 크롤러 목록으로 거를 수 있는 일반 무효 트래픽.
- **SIVT**: 클릭 농장, 위장 봇처럼 분석해야 잡히는 정교한 무효 트래픽.
- **부정 클릭(이 저장소 기준)**: 같은 사용자, 같은 광고가 마지막 과금으로부터 10초 미만에 다시 클릭한 것.

## 과금과 정산 (3-9, 3-11)

- **원장(ledger)**: 확정된 금액은 고치지 않고 정정 기록을 덧붙이는 장부 방식.
- **장부**: 이 저장소에서 클릭 하나의 처리 결과(과금 여부, 금액, 사유)를 한 줄로 남기는 테이블.
- **멱등성**: 같은 요청을 여러 번 처리해도 결과가 한 번 처리한 것과 같은 성질. 여기서는 click_id 유니크로 보장.
- **결과 확정**: 과금이든 무과금이든 판정을 끝내고 장부에 남긴 상태. 시스템 실패로 판정하지 못한 건은 확정이 아니라 다시 처리합니다.
- **무과금 사유**: DUPLICATE(재전송), INVALID_CLICK(10초 미만), BUDGET_EXHAUSTED(예산 부족).
- **워크플로 엔진(Temporal)**: 여러 외부 시스템에 걸친 긴 흐름을 단계별로 저장, 재시도, 보상하는 도구.

## 분산 처리 (3-10)

- **파티션**: 키 기준으로 나눈 메시지 묶음. 한 파티션은 한 컨슈머만 읽습니다.
- **파티션 키**: 어느 파티션으로 갈지 정하는 값. 여기서는 adId. 같은 광고는 늘 한 곳에서만 처리됩니다.
- **핫 파티션**: 큰 광고 하나에 트래픽이 몰려 파티션 하나만 바빠지는 현상.
- **최소 한 번 전달(at-least-once)**: 유실은 없지만 중복은 생길 수 있는 전달 보장. 멱등 처리와 짝을 이룹니다.
- **최대 한 번 전달(at-most-once)**: 중복은 없지만 유실이 생길 수 있는 전달 보장.
- **ACK(오프셋 커밋)**: 컨슈머가 "여기까지 처리했다"고 큐에 알리는 것. DB 커밋 뒤에 합니다.
- **이벤트 시간 / 처리 시간**: 일이 실제로 일어난 시각 / 서버가 그 이벤트를 처리한 시각. 판단은 이벤트 시간 기준.
- **워터마크**: "이 시각 이전 이벤트는 다 왔다"고 보는 기준선. 순서 뒤바뀜을 잠깐 모아 정렬할 때 씁니다.
- **Redis Streams**: Redis의 추가 전용 로그 자료구조. 컨슈머 그룹과 ACK가 있어 이 저장소에서 Kafka 대신 큐로 씁니다.

## 자체 서빙 (3-12)

- **퍼스트파티 데이터**: 플랫폼이 자기 서비스에서 직접 모은 사용자 데이터(좋아요, 최근 검색, 장바구니 등).
- **사용자 신호 보정**: 이 저장소에서 pCTR 기본값에 사용자 데이터(최근 본 브랜드)를 반영해 곱하는 배수.
- **다목적 랭킹**: 기대 수익 하나가 아니라 마진, 프로모션 같은 여러 목표를 함께 반영한 랭킹.
- **플랫폼 가중치**: 이 저장소에서 마진, 프로모션을 반영해 eCPM에 곱하는 배수. 기본 1.0.
- **블렌딩**: 일반 상품 목록과 광고를 한 목록으로 섞는 것.
- **광고 피로도(ad fatigue)**: 같은 광고를 반복해서 본 사용자가 무감각해지거나 불쾌해지는 현상.
- **frequency cap**: 같은 사용자에게 같은 광고를 일정 시간 안에 N회까지만 보여주는 상한.

## 클라이언트 쪽 유실 (3-13)

- **파라미터 체이닝**: 리다이렉트, 페이지 이동마다 트래킹 ID를 URL 파라미터로 계속 넘겨주는 것. 한 곳에서 빠지면 그 뒤가 끊깁니다.
- **ITP**: Safari의 추적 방지 기능. 쿠키 수명을 줄이거나 막아 쿠키 기반 추적을 어렵게 합니다.
- **화면 전환 경쟁 상태**: 페이지가 바뀌면서 브라우저가 이전 페이지의 진행 중 요청을 끊어 이벤트가 사라지는 현상.
- **sendBeacon**: 페이지가 닫히거나 바뀌어도 브라우저가 대신 끝까지 보내주는 작은 POST 전송 API.
- **렌더링(served) 노출**: 광고가 DOM에 그려진 노출. viewable 여부와 상관없이 셉니다.
- **IntersectionObserver**: 요소가 화면에 몇 % 보이는지 알려주는 브라우저 API. viewable 측정에 씁니다.
- **1st-party 서브도메인**: 서비스 자신의 도메인 아래 서브도메인. 광고 차단 목록에 덜 걸리고 쿠키 제약도 덜 받습니다.
- **리버스 프록시**: 클라이언트 요청을 대신 받아 뒤의 서버로 넘기는 서버. 이 저장소에서는 Nginx.

## 1단계에서 새로 나온 용어

- **경매표(auction)**: 이 저장소의 서빙 응답에 함께 보내는, 후보별 pCTR, eCPM, 점수, 순위, 낙찰가, 탈락 사유 표.
- **카탈로그 스냅샷**: 광고와 상품 목록을 주기적으로 통째로 읽어 메모리에 둔 사본. 서빙은 이것을 읽습니다.
- **장애 주입**: 일부러 지연이나 실패를 만들어 시스템이 어떻게 버티는지 보는 것. 여기서는 `debugDelayMs`.
- **서킷 상태**: CLOSED(정상 호출), OPEN(호출 차단), HALF_OPEN(차단 후 한 번 시험 호출).
- **HMAC**: 비밀키로 만든 서명. 키가 없으면 같은 서명을 만들 수 없어 내용이 바뀌었는지 알 수 있습니다.

## 2단계에서 새로 나온 용어

- **클릭 URL(클릭 리다이렉트)**: 광고 링크를 광고 서버 주소로 걸어, 서버가 클릭을 기록한 뒤 실제 랜딩 페이지로 보내는 방식.
- **랜딩 페이지**: 광고를 누른 사용자가 도착하는 페이지. 여기서는 데모 상품 페이지.
- **클라이언트-서버 대사**: 브라우저가 보냈다고 센 수와 서버가 받은 수를 비교해 유실을 찾는 일.
- **SET NX**: 키가 없을 때만 쓰는 Redis 명령. "처음 온 이벤트인가"를 원자적으로 판정합니다.
- **XADD / MAXLEN**: Redis 스트림에 항목을 덧붙이는 명령 / 스트림 최대 길이를 넘으면 오래된 것부터 잘라냄.
- **고정 창(fixed window)**: 첫 이벤트부터 정해진 시간 동안 세고, 시간이 지나면 0부터 다시 세는 방식.
- **헤드리스 브라우저**: 화면 없이 도는 자동화용 브라우저. User-Agent에 Headless가 들어가 GIVT의 대표적인 신호입니다.
